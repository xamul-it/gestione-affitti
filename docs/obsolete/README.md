## Why These Files Were Archived

These documents were archived because:

1. **UAT Reports** - Testing phases have been completed. These are historical records.
2. **QA Reports** - Issues have been resolved. Current status is in active documentation.
3. **Test Manifests** - Snapshot of test coverage at specific points in time.
4. **Auto-Generated Reports** - Temporary reports with timestamp-based filenames.

## How to Access Archived Documentation

If you need to reference historical information:

1. **For Historical Context:** Search for document names in this directory
2. **For Current Information:** Use the actively maintained documentation in `docs/`
3. **For Specific Test Results:** Look at the specific report files
4. **For Previous Procedures:** Archived guides contain procedures that may have changed

## Retrieving Historical Information

To understand what was tested or decided historically:

1. Check the UAT_FINAL_REPORT.md for comprehensive testing overview
2. Review REPORT_FIX_UAT_ISSUES.md for issues that were fixed
3. Look at REPORT_TEST_COMPLETO_AUTOMATISMI.md (if still referenced) for complete test results

## When to Reference Archived Documents

- **Regulatory Requirements:** If you need to prove testing was done
- **Bug Investigation:** If you need to understand what was tested in a specific area
- **Historical Context:** If you need to understand why decisions were made
- **Comparative Analysis:** If you want to compare old vs new approaches

## Keeping the Archive Clean

New archives should be created when:
- Major documentation reorganization occurs

- Significant project milestones are reached
